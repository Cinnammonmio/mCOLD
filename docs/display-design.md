# mCOLD — Display design

ออกแบบสำหรับ Waveshare 2.13" e-Paper (G) 250×122, 4 ink (B/W/Y/R)
mockup ทุกหน้าอยู่ที่ `display-mock/out/` สร้างด้วย `python display-mock/render.py`

renderer ใช้ palette 4 สีจริง และให้ FreeType เรนเดอร์ตัวอักษรเป็น monochrome พร้อม hinting
(ไม่ใช่ antialias แล้วมา threshold) ภาพที่เห็นจึงเป็นสิ่งที่จอแสดงได้จริง ไม่ใช่ภาพสวยบนจอคอม

## หลักการ

1. **หน้าจอเปลี่ยนตาม state เท่านั้น** บอร์ดนี้ไม่มีปุ่มใด ๆ (GPIO0 ไม่มีปุ่ม และเอกสาร
   requirement ห้ามทำปุ่ม START/STOP) ผู้ใช้พลิกหน้าเองไม่ได้ หน้า C2 เรียกด้วย NFC tap หรือ BLE
2. **หนึ่งหน้า หนึ่งคำตอบ** หน้าหลักตอบคำถามเดียวคือ "ตอนนี้กี่องศา และปกติหรือไม่"
   ที่เหลือเป็นข้อมูลรอง ตัวเล็ก เงียบ
3. **สีคือ accent ไม่ใช่พื้น** ใช้แถบซ้าย 4 px เป็นตัวบอกระดับ (เหลือง = warning, แดง = alarm)
   ไม่ถมสีเต็ม banner เพราะกินหมึกและดูไม่เรียบ และ **ทุกครั้งที่มีสีต้องมีคำกำกับ**
   (คนตาบอดสีต้องอ่านได้จากข้อความ — เป็นข้อกำหนดในเอกสาร requirement)
4. **เส้นคั่นมีแค่ 2 เส้น** หนา 1 px ใต้ header และเหนือ footer ไม่มีกรอบ ไม่มีกล่อง ไม่มีไอคอน
   จอ 4 สีไม่มี grayscale เส้นทุกเส้นจึงดำสนิท ยิ่งมีน้อยยิ่งเรียบ
5. **ทุกหน้ามีเวลาอัปเดตล่าสุด** เพราะภาพค้างบนจอเมื่อไฟดับ ห้ามใช้ภาพบนจอเป็นหลักฐานว่าเครื่องยังทำงาน

## Type scale

| บทบาท | Font | ขนาด | ใช้ที่ |
|---|---|---|---|
| micro caps (tracking 0.8) | SemiBold | 11 | header, footer, label คอลัมน์ขวา |
| body | Medium | 13 | ประโยคอธิบาย, แถว label/value หน้า C |
| status | SemiBold | 13→11 | คำสถานะใต้ตัวเลขใหญ่ ย่อเองให้พ้นคอลัมน์ขวา |
| value | Medium | 15→12 | ค่าคอลัมน์ขวา ย่อเองให้พ้น label |
| title | SemiBold | 26 | หัวข้อหน้า takeover |
| hero | Light | 58→46 | ตัวเลขอุณหภูมิ ย่อเองให้พ้นคอลัมน์ขวา |

ฟอนต์ IBM Plex Sans Thai (มีใน repo แล้ว) รองรับไทยด้วยถ้าต้องเปลี่ยนภาษาภายหลัง

## ความคมของตัวอักษร

จอไม่มี grayscale ทุก pixel เป็น 0 หรือ 1 ความคมจึงมาจาก 3 อย่าง ไม่ใช่การเลือกฟอนต์สวย

1. **เรนเดอร์เป็น monochrome พร้อม hinting ตั้งแต่ต้น** (`fontmode = "1"`)
   ไม่ใช่วาดแบบ antialias แล้วมา threshold — hinting จะดึง stem ทุกเส้นให้ลงตรงกลาง pixel
   วิธี threshold ทำให้ stem ที่ตกคร่อม pixel มีค่าไม่ถึงเกณฑ์แล้วหายไปเลย
2. **advance ต้องเป็นจำนวนเต็ม** ใช้ layout engine แบบ BASIC และปัดพิกัดทุกตัวอักษรเป็น int
   ถ้าปล่อยให้เป็นเศษ ตัวอักษรเดียวกันจะ rasterise ไม่เหมือนกันในแต่ละตำแหน่ง ดูสั่น
3. **ขนาดต้องพอกับ typeface** ไม่ใช่ทุกขนาดคม — วัดแล้วพบว่า IBM Plex Sans Thai
   ที่ 9–10 px ตัว `U`/`P` เบี้ยวทุกน้ำหนัก, **11 px SemiBold เป็นขนาดเล็กสุดที่ stem ลงล็อกครบ**
   จึงยก micro caps จาก 9 เป็น 11 px และ body จาก 12 เป็น 13 px

### สามข้อที่ได้จากการทำ mockup จริง

- **ต่ำกว่า 12 px ห้ามใช้น้ำหนักบางกว่า Medium** — ตอนทดลองด้วย Regular 11 px แบบ threshold
  เส้นตั้งของ `d` หายกลายเป็น `c` ("stopped" อ่านได้เป็น "stoppec")
- **ตัวเลขใหญ่ต้องย่อได้เอง** — `11.6` กว้างกว่า `4.2` จนหน่วย °C ไปทับ label คอลัมน์ขวา
  view model จึงต้องเลือกขนาดจากความกว้างที่วัดได้ ไม่ใช่ขนาดคงที่
- **บรรทัดสถานะก็ต้องย่อได้เอง** — พอ type scale ใหญ่ขึ้น "CHARGING IN DOCK" ล้นไปชนคอลัมน์ขวา
  ทุกข้อความที่ผู้ใช้/config กำหนดได้ต้องมีกล่องคุมความกว้าง และ renderer เตือนเมื่อล้น

## หน้าจอ 15 state / 3 template

**A — Monitor** ตัวเลขใหญ่ซ้าย + 3 ค่ารองขวา

| # | State | Accent | หมายเหตุ |
|---|---|---|---|
| A1 | IDLE / READY | — | ยังไม่มี Trip, คอลัมน์ขวาเป็น battery/storage/last sync |
| A2 | TRIP ACTIVE | — | หน้าหลัก ~90% ของเวลาใช้งาน |
| A3 | WARNING | เหลือง | สถานะบอกทั้งค่าและระยะเวลา "ABOVE 8.0 · 4 MIN" |
| A4 | ALARM | แดง | ตัวเลขเป็นแดงด้วย, footer นับ "ALARM 1 OF 3" |
| A5 | PROBE FAULT | เหลือง | อุณหภูมิเป็น `--` ห้ามเป็น 0.0, คอลัมน์ขวาเก็บค่าล่าสุด+เวลา |
| A6 | CHARGING / DOCK | — | คอลัมน์ขวาเป็น SOC/กระแส/เวลาเต็ม |
| A7 | STALE SAMPLE | — | เวลาใน header เป็นแดง + คำว่า STALE เมื่อ sample เก่ากว่าเกณฑ์ |

**B — Takeover** หัวข้อใหญ่หนึ่งบรรทัด + คำอธิบายหนึ่งประโยค (ใช้เมื่ออุณหภูมิไม่ใช่สาระ)

| # | State | Accent |
|---|---|---|
| B1 | BOOT / SELF-TEST | — |
| B2 | USB CONNECTED (read-only) | — |
| B3 | BLE SESSION | — |
| B4 | STORAGE FULL / DATA LOSS | แดง |
| B5 | CRITICAL BATTERY | แดง |
| B6 | FAULT / RECOVERY | เหลือง |

**C — Detail** 3 แถว label/value ไม่มีตัวเลขใหญ่

| # | State | Trigger |
|---|---|---|
| C1 | TRIP SUMMARY | อัตโนมัติหลัง STOP_TRIP |
| C2 | DEVICE DETAIL | NFC tap หรือคำสั่ง BLE |

## Refresh policy

| กรณี | พฤติกรรม |
|---|---|
| ค่าหรือสถานะไม่เปลี่ยน | ไม่ refresh |
| เปลี่ยนแต่ยังไม่ครบ min interval | รวมไว้รอเฟรมถัดไป |
| alarm เปลี่ยน state (เกิด/หาย/ack) | refresh ทันที ไม่รอ interval |
| เปิด/ปิด rail เพื่ออ่าน MAX6675 | ไม่ refresh (จอแชร์ rail เดียวกัน) |

min interval ที่เสนอ **15 นาที** [PROPOSED]
ประมาณการ [VERIFY ต้องวัดจริง]: full refresh ~20 s ที่ ~15 mA ≈ 0.10 mAh/ครั้ง
→ ทุก 5 นาที ≈ 210 mAh/7 วัน = ~18% ของ budget 1200 mAh
→ ทุก 15 นาที ≈ 70 mAh/7 วัน = ~6%

## ข้อจำกัดที่ยอมรับแล้ว

- **วาดหน้า "OFF" ไม่ได้** SW3 ตัดไฟทันที firmware ไม่ได้รับสัญญาณล่วงหน้า
  เฟรมสุดท้ายที่ค้างอยู่คือเฟรมก่อนหน้านั้น ผู้ใช้ต้องดูเวลาใน header เอง
- **DISPLAY_FAULT แสดงบนจอตัวเองไม่ได้** ต้องออกทาง LED + log + BLE เท่านั้น
- ตัวเลขแสดงได้สูงสุด 1 ตำแหน่งทศนิยม (MAX6675 resolution 0.25 °C
  และ resolution ไม่ใช่ accuracy — ยังไม่มีผลสอบเทียบ)

## ยังต้องตัดสินใจ

1. ภาษา: ตอนนี้เป็น English ตามที่เอกสารแนะนำ · ถ้าเปลี่ยนเป็นไทยต้องทดสอบวรรณยุกต์บนความสูง 122 px
2. min refresh interval: 15 นาที (เสนอ) หรือ 5 นาทีตามรอบ sample
3. หน้า C2 ให้ NFC tap เรียกด้วยหรือเอาแค่ BLE
4. เกณฑ์ STALE: sample เก่ากว่ากี่เท่าของ sample interval
