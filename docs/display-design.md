# mCOLD — Display design

Waveshare 2.13" e-Paper (G) 250×122 · ใช้ **3 หมึก: ขาว ดำ แดง** (เหลืองมีบนจอแต่เลือกไม่ใช้)
mockup ทุกหน้าอยู่ที่ `display-mock/out/` สร้างด้วย `python display-mock/render.py`

renderer ให้ FreeType เรนเดอร์ตัวอักษรเป็น monochrome พร้อม hinting ไม่มี antialias
และไอคอนวาดทีละ pixel ไม่ได้ย่อจาก vector ภาพที่เห็นจึงเป็นสิ่งที่จอแสดงได้จริง

## หลักการ

1. **หน้าจอเปลี่ยนตาม state เท่านั้น** บอร์ดนี้ไม่มีปุ่มใด ๆ (GPIO0 ไม่มีปุ่ม และเอกสาร
   requirement ห้ามทำปุ่ม START/STOP) หน้า C2 เรียกด้วย NFC tap หรือ BLE
2. **อุณหภูมิอยู่กึ่งกลางและใหญ่ที่สุด** min/max อยู่ล่างสุดของ body ไม่มีอะไรมาแย่งสายตา
3. **alarm คือกรอบแดงทั้งเฟรม** ไม่ใช่ป้ายเล็ก ๆ — มองเห็นได้จากอีกฝั่งของคลัง
   ระดับรองลงมาใช้ **ตัวเลขแดง** ไม่ตีกรอบ
   ไม่มีข้อความอธิบายบนหน้า monitor แล้ว (ตัด TEMP HIGH / PROBE OPEN / ABOVE ออก)
   ความหมายของแดงเหลือกฎเดียว: **ตัวเลขนี้เชื่อไม่ได้** (หลุดช่วง หรือไม่มีค่าที่ใช้ได้)
   และกรอบแดง = เป็น alarm · เหตุผลอยู่ที่ LED, log และแอป
   ข้อแลกเปลี่ยนที่ต้องรู้: เอกสาร requirement กำหนดให้สีมีคำกำกับเสมอเพื่อคนตาบอดสี
   ตอนนี้หน้า monitor ไม่มีคำแล้ว จึงพึ่ง LED/buzzer/แอป เป็นช่องทางที่ไม่ใช้สีแทน
4. **เส้นคั่นมีเส้นเดียว** เหนือ footer ส่วน header ใช้การกลับสี (ขาวบนดำ) แทนเส้น
   ไม่มีกรอบ ไม่มีกล่อง
5. **ทุกหน้ามีเวลาอัปเดตล่าสุด** เพราะภาพค้างบนจอเมื่อไฟดับ ห้ามใช้ภาพบนจอเป็นหลักฐานว่าเครื่องยังทำงาน
6. **ไม่แสดงประตูและไม่แสดง SD** บนจอ (ยัง log เหตุการณ์ประตูครบ แค่ไม่กินพื้นที่จอ)

## ความคมของตัวอักษร

จอไม่มี grayscale ทุก pixel เป็น 0 หรือ 1 ความคมมาจาก 3 อย่าง

1. **เรนเดอร์เป็น monochrome พร้อม hinting ตั้งแต่ต้น** (`fontmode = "1"`)
   ไม่ใช่วาดแบบ antialias แล้วมา threshold — hinting ดึง stem ทุกเส้นให้ลงกลาง pixel
2. **advance ต้องเป็นจำนวนเต็ม** layout engine แบบ BASIC และปัดพิกัดทุกตัวอักษรเป็น int
   ถ้าปล่อยเป็นเศษ ตัวอักษรเดียวกันจะ rasterise ไม่เหมือนกันในแต่ละตำแหน่ง ดูสั่น
3. **ขนาดต้องพอกับ typeface** วัดแล้วพบว่า IBM Plex Sans Thai ที่ 9–10 px ตัว `U`/`P`
   เบี้ยวทุกน้ำหนัก · **11 px เป็นขนาดเล็กสุดที่ stem ลงล็อกครบ**

### สิ่งที่ได้จากการวัดจริง

- **น้ำหนักบางใช้กับตัวเล็กได้ ถ้าเรนเดอร์แบบ hinted mono** — Light 11–13 px stem เหลือ 1 px
  สม่ำเสมอ ไม่มีตัวหาย (ข้อห้าม "ต่ำกว่า 12 px ห้ามบางกว่า Medium" ที่บันทึกไว้ก่อนหน้า
  เป็นข้อจำกัดของวิธี threshold เท่านั้น ตอนนี้ไม่ใช้วิธีนั้นแล้ว)
  ที่น่าสนใจคือ **Regular 11 px แย่กว่า Light 11 px** เพราะ stem หนา 1.5 px แล้วปัดไม่ลงตัว
- **ตัวอักษรกลับสี (ขาวบนดำ) ต้องหนากว่าปกติหนึ่งระดับ** หมึกจอมีการแผ่ ทำให้เส้นขาวดูบางลง
  header จึงใช้ Light 12 ไม่ใช่ Light 11 เท่าบรรทัดสถานะ
- **ตัวเลขใหญ่และบรรทัดสถานะต้องย่อขนาดเองจากความกว้างที่วัดได้** `11.6` กว้างกว่า `4.2`
  และข้อความบางอันมาจาก config ที่ผู้ใช้ตั้งได้ · renderer เตือนออกมาเมื่อมีข้อความล้นกล่อง
- **ไอคอนเล็กกว่า 8 px ใช้ไม่ได้ ต้องยอมให้สูงขึ้น** ลองวาด storage ที่ 6–7 px ห้าแบบ
  แล้วอ่านไม่ออกทั้งหมด (ทรงกระบอกกลายเป็นเลข 8 ข้าง % ของตัวเอง, การ์ดบากมุมและ chip
  กลายเป็นก้อนเบลอ) · ที่ใช้ได้คือ **ถังตั้งสูง 11 px เติมจากล่าง** เพราะ
  (ก) สูงพอให้เส้นขอบกับระดับที่เติมแยกกันออก (ข) รูปทรงไม่ซ้ำกับแบตที่วางนอน

## Footer — แถวสถานะ

ไอคอน 1-bit วาดทีละ pixel ชิดซ้าย · ค่าตัวเลขชิดขวา

**ฝั่งซ้าย — เรียงซ้ายไปขวา ของที่เพิ่มมาต่อท้ายทางขวา** ตัวที่มีอยู่แล้วไม่ขยับ

| ลำดับ | สถานะ | รูปแบบ | ตอนไม่ active |
|---|---|---|---|
| 1 | Wi-Fi | ≋ arcs | **แสดงพร้อมขีดทับ** |
| 2 | Cloud / server | ☁ | **แสดงพร้อมขีดทับ** |
| 3 | Trip กำลังทำงาน | ▶ สามเหลี่ยม | ไม่แสดง |
| 4 | การกระแทก (มี shock ใน Trip นี้) | ✳ ประกาย **สีแดง** | ไม่แสดง |

wifi/cloud อยู่สองตำแหน่งแรกเพราะแสดงตลอด ส่วน trip/shock เป็นตัวที่โผล่เพิ่ม
จึงต่อท้ายทางขวา ตำแหน่งของ wifi/cloud จึงไม่เคยเลื่อนเมื่อ state เปลี่ยน
และใช้ขีดทับแทนการซ่อน เพราะภาพค้างบนจอ ถ้าหายไปเลยจะอ่านไม่ออกว่า
"ไม่ได้เชื่อมต่อ" หรือ "เฟรมเก่าที่ยังไม่อัปเดต"

**ฝั่งขวา — เกจ + ตัวเลข ชิดขวา**

| สถานะ | รูปแบบ | เป็นสีแดงเมื่อ |
|---|---|---|
| กำลังชาร์จ | ⚡ (ซ้ายสุดของกลุ่ม) | — |
| แบตเตอรี่ | แบตวางนอน เติมตามประจุที่เหลือ + `78%` | **≤ 20%** |
| พื้นที่เก็บข้อมูล | ถังตั้ง เติมจากล่าง + `6%` | **≥ 90%** |

ตัวเลขพื้นที่เก็บข้อมูลเป็น **% ที่ใช้ไปแล้ว** ไม่ใช่ % ที่ว่าง เพื่อให้กฎ "ใกล้เต็มเป็นแดง"
อ่านไปทางเดียวกับเกจที่เติมขึ้น · ต้องรู้ไว้ว่าเลขสองตัวนี้อ่านกลับทางกัน
(แบต 90% = ดี, เมม 90% = แย่) ระดับที่เติมในเกจจึงเป็นตัวช่วยแยก

## หน้าจอ 14 state / 4 template

**A — Monitor** อุณหภูมิกึ่งกลาง + min/max ล่างสุด

| # | State | สัญญาณ |
|---|---|---|
| A1 | IDLE / READY | แถวล่างเป็น "NO ACTIVE TRIP" ไม่มี min/max |
| A2 | TRIP ACTIVE | ดำล้วน — เงียบคือปกติ |
| A3 | OUT OF BAND | ตัวเลขแดง ไม่ตีกรอบ |
| A4 | ALARM | ตัวเลขแดง + **กรอบแดง** |
| A5 | NO READING | `--` สีแดง ห้ามเป็น 0.0 · min/max ยังอยู่ |

A5 รวม PROBE FAULT กับ STALE SAMPLE เป็นหน้าเดียว เพราะเมื่อตัดข้อความออกแล้ว
ทั้งสองกรณีเหลือความหมายเดียวกันบนจอคือ "ไม่มีค่าที่ใช้ได้ตอนนี้" เหตุผลอยู่ใน log/แอป
ถ้าต้องการแยกสองกรณีบนจอ ต้องเพิ่มไอคอนใน footer อีกดวง (ต่อท้ายทางขวาตามกฎด้านบน)

**Charge — A6** ไม่แสดงอุณหภูมิ แสดงเรื่องชาร์จให้ครบ: SOC ตัวใหญ่, สถานะการชาร์จ,
แหล่งจ่าย (DOCK PD 20V), กระแสจริง, เวลาที่เหลือจนเต็ม

**B — Takeover** หัวข้อใหญ่ + คำอธิบาย + บรรทัดข้อมูล

| # | State | สัญญาณ |
|---|---|---|
| B1 | BOOT / SELF-TEST | — |
| B2 | USB CONNECTED (read-only) | — |
| B3 | BLE SESSION | — |
| B4 | STORAGE FULL / DATA LOSS | กรอบแดง |
| B5 | CRITICAL BATTERY | กรอบแดง |
| B6 | FAULT / RECOVERY | หัวข้อแดง ไม่ตีกรอบ |

**C — Detail** 3 แถว label/value · C1 TRIP SUMMARY (อัตโนมัติหลัง STOP_TRIP) ·
C2 DEVICE DETAIL (NFC tap หรือ BLE)

## Refresh policy

| กรณี | พฤติกรรม |
|---|---|
| ค่าหรือสถานะไม่เปลี่ยน | ไม่ refresh |
| เปลี่ยนแต่ยังไม่ครบ min interval | รวมไว้รอเฟรมถัดไป |
| alarm เปลี่ยน state (เกิด/หาย/ack) | refresh ทันที ไม่รอ interval |
| เปิด/ปิด rail เพื่ออ่าน MAX6675 | ไม่ refresh (จอแชร์ rail เดียวกัน) |

min interval ที่เสนอ **15 นาที** [PROPOSED]
ประมาณการ [VERIFY ต้องวัดจริง]: full refresh ~20 s ที่ ~15 mA ≈ 0.10 mAh/ครั้ง
→ ทุก 5 นาที ≈ 210 mAh/7 วัน = ~18% ของ budget 1200 mAh
→ ทุก 15 นาที ≈ 70 mAh/7 วัน = ~6%

header ที่กลับสีเป็นพื้นดำไม่กินพลังงานเพิ่มหลัง refresh เสร็จ เพราะจอเป็น bistable

## ข้อจำกัดที่ยอมรับแล้ว

- **วาดหน้า "OFF" ไม่ได้** SW3 ตัดไฟทันที firmware ไม่ได้รับสัญญาณล่วงหน้า
  เฟรมที่ค้างอยู่คือเฟรมก่อนหน้านั้น ผู้ใช้ต้องดูเวลาใน header เอง
- **DISPLAY_FAULT แสดงบนจอตัวเองไม่ได้** ต้องออกทาง LED + log + BLE เท่านั้น
- **header กลับสีแล้วใส่สีแดงในนั้นไม่ได้** แดงบนพื้นดำแยกไม่ออก
  สถานะ STALE จึงย้ายมาอยู่บรรทัดสถานะใน body ไม่ใช่ข้าง ๆ เวลา
- ตัวเลขแสดงได้สูงสุด 1 ตำแหน่งทศนิยม (MAX6675 resolution 0.25 °C
  และ resolution ไม่ใช่ accuracy — ยังไม่มีผลสอบเทียบ)
