# bringup

เฟิร์มแวร์สำหรับไล่ทดสอบบอร์ด mCOLD Foam V.1 ตัวจริงทีละโมดูล
**ไม่ใช่แอป** — มันเปิดราง 1 ราง คุยกับชิป 1 ตัว บอกว่าได้อะไรกลับมา แล้วปิดรางนั้น

```bash
pio run -t upload -e mcold
pio device monitor -e mcold
```

พิมพ์คำสั่งในเทอร์มินัล กด Enter · `?` ดูรายการทั้งหมด

## ก่อนจ่ายไฟ — ทำด้วยมัลติมิเตอร์ ไม่ใช่ด้วยเฟิร์มแวร์

เฟิร์มแวร์ตัวนี้ช่วยอะไรไม่ได้เลยถ้าบอร์ดช็อต และการเสียบ USB เข้าบอร์ดที่ช็อต
อาจพังทั้งบอร์ดและพอร์ต ทำสามข้อนี้ก่อนเสมอ

1. **ส่องดูด้วยตา** — ขา QFN/QFP ติดกันไหม, tombstone, คราบ flux ข้ามขา
   โดยเฉพาะ U12 (TPS63020) และ U4 (BQ25601) ที่เป็น power
2. **วัดความต้านทาน 3V3_MAIN ↔ GND** ตอนยังไม่จ่ายไฟ ถ้าใกล้ 0 Ω คือช็อต **หยุด**
   ค่าปกติควรเป็นหลัก kΩ ขึ้นไป (จะค่อย ๆ ขึ้นเพราะ C ชาร์จ)
3. **วัด CELL_PLUS ↔ GND** เหมือนกัน ก่อนเสียบแบต

ถ้ามีแหล่งจ่ายปรับกระแสได้ ให้จ่าย 5 V จำกัดกระแสที่ ~150 mA ก่อน
บอร์ดที่ปกติจะกินไม่ถึง — ถ้าชนลิมิตทันทีแปลว่ามีอะไรผิด

## ลำดับการไล่

ไล่ตามนี้ อย่าข้าม เพราะแต่ละขั้นเป็นฐานของขั้นถัดไป

| # | คำสั่ง | ตอบคำถามว่า |
|---|---|---|
| 1 | `info` | MCU บูตไหม และเป็น N16R8 จริงไหม |
| 2 | `pins` | ขา input ค้างไหม ตอนยังไม่เปิดรางอะไรเลย |
| 3 | `scan` | บัส I2C มีชีวิตไหม และกี่ตัวจาก 8 ที่ตอบ |
| 4 | `id` | ตัวที่ตอบนั้น**คุยได้**จริงไหม ไม่ใช่แค่ ack |
| 5 | `rail epd on` → `temp` | รางจอ/เทอร์โมคัปเปิล + MAX6675 |
| 6 | `gnss 15` | ราง SD/GNSS + UART |
| 7 | `rail led on` → `walk` | ราง LED + ลำดับการต่อ 4 ดวง |
| 8 | `buzz` | Q5 + buzzer |
| 9 | `chg on` → `id` | charger เริ่มทำงานไหม (ดู REG0B) |

`all` รันข้อ 1–4 รวดเดียว ทั้งหมดเป็น read-only และไม่เปิดรางอะไร

## สิ่งที่เฟิร์มแวร์ตั้งใจ**ไม่**ทำตอนบูต

- **ทุกรางปิด** — `EPD_TK` และ `SD_GNSS` เป็น LOW, `LED` เป็น HIGH (P-MOS ปิดเมื่อ HIGH)
  บอร์ดใหม่ที่เปิดทุกอย่างพร้อมกันบอกไม่ได้ว่าโหลดตัวไหนดึงรางตก
- **ชาร์จปิดอยู่** — `CHG_CE_N` ถูกขับ HIGH เพราะยังไม่ได้ตรวจ charger กับ
  current monitor บนบอร์ดนี้ ระบบยังมีไฟจาก USB ผ่าน power path ของ BQ25601 อยู่ดี
  จึงไม่เสียอะไรที่จะรอให้สั่ง `chg on` เอง · ถ้าอยากให้บูตมาแล้วชาร์จเลย
  แก้บรรทัดเดียวใน `setup()`
- **ไม่แตะจอ** — วงจร boost ของ e-paper (L7/Q3/PREVGH/PREVGL) มีลำดับการเปิดที่ต้องตรง
  กับ controller ขอตรวจรางกับ MAX6675 ให้ผ่านก่อนแล้วค่อยทำจอแยกเป็นอีกขั้น
- **ไม่แตะ SD** — อยู่รางเดียวกับ GNSS ทำทีหลัง

## เรื่องที่ต้องรู้เกี่ยวกับบอร์ดนี้

**GPIO43/44 คือขา console ของ ROM** บนบอร์ดนี้มันเป็นเส้นข้อมูล LED กับ charger enable
แอปพลิเคชันจึงเปิด UART0 บนสองขานี้ไม่ได้ — console ต้องเป็น USB CDC เท่านั้น
และ ROM bootloader จะพ่นข้อมูลออก GPIO43 ตอนบูต ทำให้ LED ดวงแรกกระพริบสีมั่วก่อน
เฟิร์มแวร์เขียนทับครั้งแรก — ไม่ใช่ความผิดปกติ

**GNSS RX/TX ตั้งชื่อจากฝั่งโมดูล** MCU **ส่ง** ออก GPIO17 และ **รับ** เข้า GPIO18
อ่านจากชื่อ net แล้วตั้ง RX=17 จะเงียบสนิทโดยหาสาเหตุไม่เจอ

**0x53 กับ 0x57 คือ ST25DV ตัวเดียวกัน** ไม่ใช่สองชิป — user/dynamic กับ system
อยู่คนละ address

**เปิด SD เท่ากับจ่ายไฟ GNSS ด้วย** ไม่มีขาแยก

**`--flash_size` ของ image ต้องเป็น 16MB** `board_build.flash_size` อย่างเดียวไม่พอ
ต้องมี `board_upload.flash_size` ด้วย ไม่งั้น binary จะประกาศ 8 MB ตามเดฟคิทมาตรฐาน

## อ่านผลยังไง

- **`scan` ไม่มีใครตอบเลย** → สงสัย SDA/SCL, pull-up หรือ 3V3_MAIN ก่อน
  อย่าเพิ่งสงสัยชิปตัวใดตัวหนึ่ง
- **`temp` ได้ `0x0000` หรือ `0xFFFF`** → ไม่ใช่อุณหภูมิ แต่คือบัสอ่านได้แต่ 0 หรือ 1
  ซึ่งเป็นหน้าตาของชิปที่ไม่มีไฟหรือสาย MISO ตาย
- **`temp` บอก THERMOCOUPLE OPEN** → เป็น fault ไม่ใช่ 0.0 °C · ถ้ายังไม่เสียบโพรบ
  นี่คือผลที่ถูกต้อง
- **`gnss` ได้ประโยคว่าง ๆ** → โมดูลยังไม่จับดาว แต่**สายถูก** ถือว่าผ่าน
  ที่ไม่ผ่านคือไม่มีไบต์ออกมาเลย
- **`id` บอก PCF8523 OS=1** → คริสตัลไม่เคยเดิน เวลาที่เก็บอยู่ใช้ไม่ได้ ต้องตั้งใหม่
- **`walk` ดวงแรกไม่ใช่ดวงข้างเครื่อง** → chain ต่อกลับทาง และกฎทุกข้อใน
  `../docs/led-design.md` จะเลื่อนไปหนึ่งดวง
